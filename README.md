# Panatieri's Pizza — stock, ordering and distributor pricing

Same codebase as the Mamma Mia / Montana's truck apps and Main Kitchen,
reseeded from the pizzeria's printed sheets and extended with a Prices screen
that compares Ferraro against Destefano. Single `index.html` (inline
HTML/CSS/JS) + `sw.js` + `manifest.json` — drop the folder on GitHub Pages and
it runs.

Carried over unchanged: Today / Stock / Waste / Money, one-handed Got it /
Need it, offline-first localStorage with Apps Script sync, EN/ES toggle, PIN on
the Money screen, installable PWA.

## What's seeded

211 stock items across 21 categories, in 6 groups:

| Group           | Categories |
|-----------------|------------|
| Kitchen         | Frozen Meats, Seafood, Dairy, Frozen Vegs/Sides |
| Produce         | Produce |
| Dry goods       | Pasta, Canned Goods, Tomatoes, Flour, Spices, Oil, Vinegar, Misc Kitchen |
| Sauces & sweets | Wing Sauces, Dressings, Dessert |
| Supplies        | Paper/Plastic/Foil, Cups/Containers, Boxes/Bags, Catering, Cleaning, Other |
| Safety          | Safety/Ops |

Plus 4 non-stock items on Safety/Ops carried over from Main Kitchen: fire
extinguisher inspection and hood/filter cleaning (date checks), walk-in cooler
34–40°F and freezer -10–10°F (reading logs).

Rosemary appears twice on the sheets — dry under Oil, fresh under Produce. The
item id is derived from the name, so they are seeded as `Rosemary (dry)` and
`Rosemary (fresh)`. Item names must stay unique for that reason.

`Other` exists as a category because `normalize()` falls back to it for any
item whose category it doesn't recognise. Don't remove it — items would land in
a category no group lists and disappear from the Stock screen.

Beverages and Deli Meats are on Main Kitchen's sheets but not the pizzeria's,
so they aren't seeded here. Adding a category is a two-line change (`GROUPS`
plus a `CAT_ES` entry).

## The Prices screen

Behind the same PIN as Money — one unlock covers both for the session.

Each item gets a **compare unit** (lb, ea, gal…) and, per distributor, a
**price** and **how many of that unit are in their case**. The screen compares
unit cost, not sticker price:

| | Ferraro | Destefano |
|---|---|---|
| Price | $48 | $52 |
| Per case | 30 lb | 40 lb |
| Unit cost | $1.60/lb | **$1.30/lb** |

Destefano wins despite the higher sticker. Leave both case quantities blank and
it compares sticker price instead, and labels the row *sticker price only* so
you know the comparison isn't pack-adjusted.

Four states per row, shown in the CSV's `Basis` column:

- `unit` — both sides pack-adjusted, the comparison is trustworthy
- `sticker` — at least one side had no case quantity, compared on price alone
- `single` — only one distributor quotes it
- `none` — nobody has priced it

The footer totals what you'd **actually pay each** if you sent the split the app
worked out — not the whole list priced at each distributor. Those two numbers
look comparable but aren't: whichever distributor stocks fewer of your items
always looks cheaper, because what they don't quote counts as zero.

**Renaming distributors** — Settings. Prices are keyed to internal ids `v1`/`v2`,
so renaming Ferraro keeps every price already entered against it.

## Ordering

Tapping Need it and sending produces one order per distributor, each with its
own estimated total, plus a third block for anything not yet priced. Unpriced
items are never dropped or silently assigned — a half-priced catalogue must not
lose items off the order.

## Tests

```
npm test
```

20 tests, no dependencies. `tests/pricing.test.mjs` extracts the block between
the `PRICING-CORE-START` / `PRICING-CORE-END` markers straight out of
`index.html` and runs it under node, which is why everything between those
markers must stay pure — no `doc`, no `lang`, no DOM. `tests/seed.test.mjs`
parses `SEED`, `GROUPS` and the translation maps and checks counts, uniqueness
and full ES coverage.

Note `node --test tests/` does **not** work on node 26 (it tries to load the
directory as a module). Use `npm test`.

## What to tweak first

- **Order quantities** — the `par` value in each `SEED` row is what shows on the
  order list. They're guesses of 1–2; set them to your real order sizes.
- **Compare units** — blank until you set them. Until an item has one, its two
  prices compare on sticker only.
- **Icons** — a cream pizza slice on basil green, generated by
  `tools/mkicon.py`. Deliberately unlike Main Kitchen's wine square so the two
  are distinguishable on a phone home screen. Swap in the real logo when you
  have one; re-run that script if you just want to tweak the colours.
- **Colour** — `--basil` in `:root` is the accent (basil green `#1E5B3A`,
  chosen to be distinguishable from Main Kitchen's wine at a glance). Also set
  `theme-color` in the `<meta>` tag and `manifest.json` to match.

## Storage keys are deliberately namespaced

GitHub Pages serves every one of our apps from `jaylaantaylor-boop.github.io`,
and **both localStorage and Cache Storage are scoped per origin, not per path**.
`DOC_KEY`, `PREFS_KEY` and the service worker's `CACHE_PREFIX` are all
panatieris-specific for that reason. Reusing Main Kitchen's would have the two
businesses silently overwriting each other's data and offline shells.

## Running it locally

```
python3 -m http.server 8788
```

Then open http://localhost:8788. Service workers need https (or localhost), so
install-to-homescreen only works once it's on GitHub Pages.
